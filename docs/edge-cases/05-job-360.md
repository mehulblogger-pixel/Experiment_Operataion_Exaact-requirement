# Module 05 — Jobs (Job 360) · Edge-case analysis (pre-build)

**Status:** ✅ BUILT (2026-08-24). Additive Stage·Owner·Blockers header via `job_now()`; tab/fold
structure untouched (asserted by tests in `tests/test_module05_job360.php`). P1.

---

## 0. Headline: the job screen is already a 360 — one thing is missing

The job detail screen is already rich: **4 tabs** (Overview · Schedule & site · Reports & QA ·
Money), a **nowband** (current-state + next-action heuristic), a **glance chip index**
(reports/releases/QAP/NCR/invoices/expenses/photos), plus panels for schedule, site check-in,
hold/witness, reports (with Module 06 applicability), costs/profitability and billing. Tests
pin the exact tab labels, folds, glance keys and role gates.

**The one clear gap vs the universal-UX rule** ("Where am I / Who's responsible / What's
blocking"): there is **no single Stage · Owner · Blockers header**. The nowband gives *next
action* but **not the current owner**, and blockers are **scattered** across separate banners
(HOLD, hold/witness, bills-missing, contract-gap, lock). Module 05 = one consolidated status
header, reusing the existing helpers. Nothing restructured.

## 1. Proposed additive layer

1. **`job_now($job)`** — a read-only helper returning `['stage', 'owner', 'blockers'=>
   [{label, href, money}]]`:
   - **stage** — the real `JOB_STAGES` label (today shown only in a fold), or "Closed".
   - **owner** — who the ball is with now, from the same pipeline the nowband uses + report
     state: Coordinator (schedule it) → Inspector → Reviewer/approver → Inspector (close it) → —.
   - **blockers** — consolidated from existing helpers: `job_lock_state` (locked),
     `job_hold_reasons` (HOLD), open **hold/witness** points (status `OPEN` via `hwp_for_job`),
     and **bills required** (`job_bills_missing`, tagged `money`). Each with an in-page `#href`.
2. **A compact status header strip** above the existing nowband: **Stage** · **Owner** ·
   **Blockers** (each blocker a chip linking to its panel). The nowband stays as the
   narrative next-step below it.

No new permission, no new route, no change to tabs/folds/glance/gates.

## 2. Edge cases

1. **Closed job** → stage "Closed", owner "—", blockers hidden (nothing waiting).
2. **Not scheduled** → owner "Coordinator (schedule it)".
3. **Scheduled, no report yet** → owner the inspector (by name), "the inspector" if unnamed.
4. **Report(s) exist, one at VETTING/UNDER_REVIEW** → owner "Reviewer / approver" (ties to
   Module 07); the field inspector is no longer the owner.
5. **Report issued but job still open** → owner "<inspector> (close the job)".
6. **No inspector assigned** → owner falls back gracefully ("the inspector"/coordinator), never
   a fatal on a null name.
7. **Locked job** → a "Locked — edits frozen" blocker; still shows stage/owner.
8. **Field inspector viewing** → **money blockers (bills required) are hidden** from them (the
   bills panel already is), matching `$fieldInspector` gating; non-money blockers still show.
9. **Blocker helper missing / errors** → each probe is `function_exists`-guarded and wrapped in
   try/catch; a broken helper drops that blocker, never breaks the header.
10. **Deputation job** → the header still renders (deputation has its own panel; stage/owner
    still meaningful).
11. **No blockers** → the Blockers line is omitted (not an empty "Blockers: none" if it reads
    as clutter — show "No blockers" only when the job is active and clear).
12. **Mobile** → single-column; chips wrap; header sits above the fold on a phone.
13. **Deep-link** → blocker chips use existing `#reports` / `#holdpoints` / `#bills` anchors
    that the existing `openForHash` script already expands.

## 3. Backward-compat / guardrails

  `test_job_screen_simplify`, the `job_glance` keys, `$fieldInspector` and `$canSeeProfit`
  gates, and the `openForHash` opener are all untouched. The header is a new strip added
  **above** the tab container.
- No status/transition/permission/PDF/template changed.
