# M3 CORRECTION #12 — COMPLETION REPORT

Answering the seventeen required points in order.

### 1 · X1 root cause
`act_set_cond_key()` returned `STORED` whenever PDO did not throw. An `UPDATE`
that matches no row is a valid statement: it writes nothing and throws nothing.
A nonexistent activity id and an id belonging to **another workspace** both
reported `STORED` having written nothing anywhere. Because EXAACT is
one-database-per-tenant, a foreign id is simply absent from the connected
database, so the cross-workspace case and the nonexistent case are the same bug.

### 2 · X1 implementation correction
The result is now decided by **reading the value back** from the intended
record in the intended connection: no row → `FAILED`; value not equal to the key
→ `FAILED`; otherwise `STORED`. `rowCount()` was rejected on measured evidence —
on MariaDB a re-write of an identical value affects **0** rows, so
`rowCount() > 0` would report `FAILED` for a correct idempotent write while
still not distinguishing "no such row" from "already correct". The read-back is
engine-independent and also catches silent truncation, which neither
`rowCount()` nor an exception would surface.

### 3 · X1 zero-row tests
A write to an id that does not exist reports `FAILED`, with a reason naming the
cause — on both engines.

### 4 · X1 cross-workspace tests
A write addressed to an id owned by another workspace reports `FAILED`, and the
row in the owning workspace is separately confirmed **unchanged**.

### 5 · Proof that `STORED` equals actual persistence
Every `STORED` in the suite is followed by a direct `SELECT` of that row showing
the key present and identical — including the idempotent re-write, which must
stay `STORED` and does.

### 6 · Four independent channel tests
`core`, `col`, `idx` and `write` each get their own five-step section: a genuine
error in A, **asserted still standing at the moment of the switch**, unreadable
in B, B's own recorded, A clean on re-entry, both workspaces repaired only
afterwards. Two channels had no independent reader in the product
(`act_optional_error()` returned `col ?: write`); `act_cond_column_error()` and
`act_cond_write_error()` were added as pure read-only accessors so each channel
can be observed alone.

### 7 · Four independent channel mutations
`M-X2-CORE`, `M-X2-COLUMN`, `M-X2-INDEX`, `M-X2-METADATA` — each makes exactly
one channel ignore the workspace. All four caught by **their own** channel's
assertion, with the mutated channel's own message in the failure text.

### 8 · Proof that DB A ≠ DB B
`$whoAmI()` asks the database itself (`SELECT DATABASE()` on MariaDB, the
resolved `sqlite_path` on SQLite). A, B and C resolve to three different
identities, and a row written in A is not visible in B.

### 9 · Workspace switching sequence
Repoint the connection → `db(true)` → `db()` rebuilds from `config.php`. This is
the application's real path, the same one "Log in as", provisioning and the
tenant sweep take. `$GLOBALS['__db_epoch']` is never assigned by hand; six
switches produce six distinct epochs issued by `db()` itself.

### 10 · Contamination result
None. No channel carried a message across a real workspace switch, in either
direction, on either engine — and this is now a claim with teeth, because each
channel was proved full at the moment of the switch.
